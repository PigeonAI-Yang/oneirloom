# Build a mascot identity system

## Select this recipe

Use when a character contributes to brand recognition and personality. Inspect the approved character and mark first. Design a new character only when the task includes that work; the recipe does not authorize replacing an existing character.

## Define the family

Separate the character's expressive illustration role from the readable master mark and wordmark. Carry meaningful silhouette, parts, connections, color, and action across these roles, with detail adapted to actual size. A detailed illustration may accompany a compact mark without becoming that mark.

Connect character shapes, wordmark weight, auxiliary graphics, and application rhythm through deliberate visual relations. Preserve how the character's parts support its meaning. For a user-defined dream-weaving creature, the relevant constraints might include four purple fluffy tentacles and their relationship to a dream-catching net. Those facts apply only when the current character and brief establish them; they are not requirements for other mascots.

Derive patterns or framing motifs from meaningful character elements instead of scattering arbitrary decorative copies. Keep text clear and the character's role consistent across compact and expressive uses. Character recognition does not justify obscuring the brand name.

## Adjust the content and components

Resolve the existing character facts and approved views, any authorized new design, exact brand names, expression range, color roles, lettering relationship, and real applications. A community brand might use an avatar, a welcome card, and a product header as a representative proposal. Choose the actual set from the context.

Include a coherent master-mark inventory and manual under the [delivery guide](../../references/vi-deliverables.md). Add icon families or expression stickers only when requested. Route them through the method's specialist links with the same identity constraints. Use character sheets only when view continuity is needed.

## Resolve this production brief

Replace the bracketed fields with inspected facts and resolved design decisions. This brief covers the family rather than a single mascot image.

```text
Create the agreed visual identity for [exact brand names], using [approved character or authorized new character brief]. Preserve [meaningful silhouette, parts, connections, colors, and action] and [approved marks or other fixed assets]. Express [user-established personality] through [specific visible character behavior and visual treatment].

Use [master mark and wordmark relationship] for brand identification, with [required lockups, monochrome and reverse versions] and [small-size treatment]. Keep the detailed character illustration available for [expressive contexts]. Adapt detail by scale while preserving [recognition and meaning anchors]. Relate the lettering, supporting typography, palette roles, and auxiliary graphics through [resolved shape, weight, rhythm, and color relationships].

Create [actual application list and formats] using [exact content]. Give the character a defined role in each application, with readable text and consistent brand identification. Include [only requested icon or sticker extensions] under the same identity rules. Assemble a guideline book for mark use, character use, type, color, graphics, applications, and actual files. Deliver [master assets], [application artwork and exports], and [manual]. Distinguish completed files from proposed variants, untested small-size simplifications, font unknowns, and pending production checks.
```

For a single concept-board request, describe the resolved character, wordmark, color and type system, and chosen applications in a complete board prompt. Label the output as a concept board and keep the system brief available. Follow the main contract for complete Chinese and equivalent English image prompts. A board does not deliver individual mascot poses, icon files, sticker cutouts, or vector marks.

## Inspect the result

Compare every depicted character to the approved identity and intended meaning before counting local features. Check small-size recognition separately from the detailed illustration. Inspect names, shape relationships, typography, color roles, and the character's scale within each application. Confirm that an expressive extension has not silently become a new master mark or new character canon.
