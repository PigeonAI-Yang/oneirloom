# Solid UI family starter

## Selection

Use for functional icons whose meaning reads through a filled silhouette, with internal openings where needed. Match a supplied solid family before using this starter's choices. A solid icon is not automatically an outlined icon with every enclosed region filled.

## Visual anchors

Balance filled mass across the family. Keep the outer contour distinct and preserve counters that distinguish the represented object or action. Use one corner and curve language, with comparable apparent weight across compact and elongated forms. Simplify small details without removing the feature that separates two meanings.

If the interface needs selected, active, or other states, preserve the metaphor while designing the requested native differences. Filling every opening or changing color alone is not an assumed state system.

## Adjustable slots

Resolve semantic labels, metaphors, display sizes, family reference, viewBox, filled shapes, counter widths, corners, palette behavior, required states, and file naming. Derive these values from the current brief. Existing state conventions take precedence over new variants.

Use the specification for code-native vector work. For prompt-only work, return complete Chinese and English prompts with the resolved visual construction. Keep production checks outside those prompts.

## Production specification

```text
Create [exact asset count and semantic labels] as a solid UI icon family for [interface context] at [actual display sizes]. Deliver separate [requested vector format] files using [file naming convention]. Match [observed reference family or chosen construction language].

Use the following resolved meanings and silhouettes: [label-to-metaphor mapping]. Preserve [distinctive semantic features]. Build each icon from filled geometric forms with [corner and curve language]. Use [viewBox and guides] to support consistent placement. Adjust individual bounds and mass optically so that narrow and broad forms belong to the same family.

Keep [required negative counters and separations] open at the smallest display size. Resolve overlapping shapes so that the final silhouette and openings express the intended object or action. Use [currentColor or specified colors] on [intended backgrounds]. Apply [requested state differences] only to [icons and states in the brief], retaining the base meaning.

Provide genuine vector geometry, individual editable assets, a label-to-file mapping, and a rendered family preview. Inspect the delivered files at [actual sizes and requested themes], including relevant state variants. Report any merged counter, indistinct silhouette, uneven mass, clipping, or unverified context. Keep fixed brand artwork and literal characters intact.
```

## Critique against the current brief

Inspect the smallest counter and the heaviest-looking asset at normal size. Compare similar meanings side by side. Check that a state's changed shape still belongs to the same family and remains distinguishable in its intended context. Avoid making every asset equally dense at the cost of recognition.

Only call the delivered family inspected after viewing actual renders. A valid file extension and a preview board do not establish usable individual assets.
