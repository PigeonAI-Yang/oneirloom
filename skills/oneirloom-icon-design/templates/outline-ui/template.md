# Outline UI family starter

## Selection

Use for a coherent family of functional line icons. An existing outline family is the construction reference when supplied. Use the solid template for a family whose identity comes from filled silhouettes. Use the app-symbol template for a product identifier.

## Visual anchors

Keep one stroke language, compatible caps and joins, and a clear relation between corners and curves. Compare visual weight across narrow, wide, circular, and diagonal shapes. Preserve gaps where parts would otherwise merge at the intended display size. Let each metaphor determine its outline instead of forcing every icon into the same occupied rectangle.

These anchors are design criteria, not observations of a supplied example. Inspect the actual reference before using them to describe its style.

## Adjustable slots

Resolve the semantic labels and metaphors, current family reference, display sizes, viewBox, stroke treatment, corners, gaps, color behavior, requested states, and output format. Choose any missing construction values for the current brief and identify them as choices. No fixed grid or stroke width is universal.

For a code-native vector brief, use the production specification below. For prompt-only work, turn the resolved design into complete Chinese and English prompts under the main output contract. Retain literal requested labels and omit unresolved placeholder text.

## Production specification

```text
Create the requested outline icon family for [interface context] at [actual display sizes]. Deliver [semantic label list and exact asset count] as individual [requested vector format] assets with [file naming convention]. Use [inspected family reference or explicitly chosen visual language].

Represent each meaning with its resolved functional metaphor: [label-to-metaphor mapping]. Preserve [features that distinguish these meanings]. Use [viewBox and construction guides], [stroke treatment], [cap and join language], and [corner language]. Balance the apparent weight of circular, narrow, wide, and diagonal forms. Center by optical appearance within the chosen bounds. Keep [resolved internal openings and part separations] visible at the smallest intended size. Adapt guides to the actual metaphor where rigid alignment would obscure its meaning.

Use [currentColor or chosen colors] against [intended interface backgrounds]. Include [only the requested states and their resolved differences]. Preserve supplied brand assets and literal characters that the brief fixes. Keep asset artwork limited to the required icon content.

Construct genuine editable vector geometry for each icon. Provide the individual source assets, a label-to-file mapping, and a rendered family preview. Inspect the actual output at [normal display sizes and requested themes]. Report any ambiguity, stroke inconsistency, closed gap, clipping, or unverified rendering context before claiming the set is ready.
```

## Critique against the current brief

Check whether users can distinguish the requested meanings without relying on the file names. Compare diagonal and circular stroke appearance at actual display size. Inspect the narrowest openings and separated components. Correct geometry when necessary rather than adding decorative detail to compensate for an unclear metaphor.

If only prompts were requested, report that legibility remains untested. If assets were requested, a contact sheet without individual files is incomplete.
