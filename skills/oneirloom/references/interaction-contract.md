# Shared interaction contract

Read this contract before the first substantive response from any Oneirloom entry unless its unchanged content is already available. Apply output clauses only to the requested deliverable. This file supplies shared policy, not another task route.

## Keep the current task

Carry the user's confirmed model, entry, reference roles, output preferences, successful details, and latest change. Keep compact internal notes or the existing task record for facts and their sources, unknowns, creative choices, intended use, audience when known, style, and current edit. Do not create a schema, service, or separate ledger. A direct capability entry uses the current conversation itself.

Current explicit choices override defaults, and confirmed conversation choices override generic recipes. Example subjects and props are not requirements. Ask only when a missing input blocks the requested outcome or changes its path. Missing optional data or tools block only dependent work. Unknown entries can receive portable text.

For an edit, change the requested main dimension where possible and preserve other valid decisions. A background change preserves the current subject, copy, layout, and medium unless a coupled adjustment is necessary. Explain that adjustment briefly. An explicit rejection replaces the affected creative direction while retaining valid facts and choices. Obtain a missing current target instead of inventing continuity. An ordinary revision request is not itself evidence of a failed result.

For person prompts, including new images and grid panels, read the person-defaults reference linked directly by the active entry. Preserve explicit choices and source traits.

## Deliver the requested output type

For native SVG, code, asset sets, or guidelines, use the capability's artifact contract and return actual usable source or files with relevant previews. A specification is not a finished artifact. For articles, use the requested article format. For existing-image prompt cards, preserve the supplied prompt and use the card's language and layout rules. These requests do not automatically require new bilingual prompts or image generation.

For prompt-only work, return complete usable prompts for the chosen path. Direct generation describes the whole image. A selected composite path includes its necessary asset prompts and assembly guidance. Do not force asset-only delivery or a layout plan onto every request.

For each required image or asset and each explicitly requested model, return a complete Chinese prompt followed by a semantically equivalent English prompt. Use one portable version when no model is selected. Follow an explicit single-language or other language-scope request instead. Preserve every visual relation across versions and keep literal in-image copy unchanged.

Put each complete prompt in its own copyable block. Keep titles, numbering, language labels, explanations, reference roles and inputs, masks, seeds, and other controls outside. Supply controls only when the actual entry confirms them and they are useful. Return complete revised prompts, not fragments that depend on previous blocks.

Write affirmative, concrete, observable target states: shape, position, direction, coverage boundaries, openings, connectors, layer order, and material appearance. Replace abstract fidelity commands and negated failed variants with the intended visible construction. This is a semantic rewrite, not a ban on individual words. Preserve literal image text and required relations. State decisive spatial, scale, and occlusion relations first and supporting details once. Check both that every required relation survives and that each visual claim comes from evidence, user intent, or an applicable default.

Keep counterexamples, error lists, and acceptance commentary internal unless requested. Requested analysis stays outside generation prose. Supply a separate negative prompt only when explicitly requested or required by a confirmed entry's separate negative field. Keep that field separate from affirmative prose. Other formats and alternatives remain request-dependent.

For portable Doubao use, separate collaborating-assistant instructions from complete prompts for the image tool. Put ordinary reference-upload guidance outside prompt blocks. Portable text establishes no native Skill installation or invocation, guaranteed identity lock, label recovery, or unsupported entry controls.

## State what the evidence establishes

Distinguish authored prompts, produced assets, assembled artifacts, and inspected results. State actual inspection status and unresolved dependent gaps. A completed queue is not visual inspection. A prompt without an inspected generated result remains visually untested.

Do not invent original prompts, camera specifications, model capabilities, settings, or success rates. A stored example demonstrates its recorded prompt and known settings, not a later edited scaffold. Preserve historical prompts, images, and known metadata. One accepted result does not establish repeatability. A user report supports a reported-result judgment, not a claim that you inspected the image.
