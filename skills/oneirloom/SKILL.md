# Oneirloom

Oneirloom is the public name of this skill collection. Treat "织梦师", "织梦师Skill", "Oneirloom", and "Oneirloom Skill" as names for this main skill when the user requests visual prompting or its other supported work. The main technical invocation is `$oneirloom`. Method skills use the `oneirloom-` namespace.

## Workflow

1. Inherit the user's confirmed model, entry, reference roles, successful details, and output preferences. Identify the deliverable: new image prompt, graphic design, expression sticker pack, icon assets, brand visual identity, reference reconstruction, edit, character sheet, result diagnosis, cross-model adaptation, tutorial, or image-and-prompt card. Distinguish prompt-only work, concept previews, specifications, and finished usable files. Ask only when a missing input changes the task path; an unknown entry need not block portable text.
2. Select the required method skills below. For reference reconstruction, always load `oneirloom-visual-analysis` and its reconstruction workflow before drafting. For graphic-design work, including sticker, icon, and brand identity requests, select the specialist method where applicable and read `oneirloom-style-design` and its [graphic-design SOP](../oneirloom-style-design/references/graphic-design-sop.md). Its first stages are Understand, Observe, and Design. Inspect subject identity and meaning during understanding, then the actual style image during observation, before consulting a recipe. The SOP owns graphic process order; visual analysis supplies evidence discipline and applicable subject checks. Add camera/composition for visible pose or framing, and color/light for decisive colors, transparent fabrics, or illumination. Resolve each exact skill name through the host catalog; the repository fallback is `../<name>/SKILL.md`. Read the file explicitly: a Markdown link does not invoke a skill. If a branch is unavailable, report that limitation and continue the reachable general work.
3. Form one internal visual specification from user intent and visible evidence. Graphic designs carry the SOP's understanding of intent and subject, observed relations, and adaptation decisions in the same internal notes. Explain how transformations preserve meaning and identity while resolving crop, hierarchy, and overlap. For static ecommerce visuals based on a real product, use `oneirloom-product-art-direction` to inspect product evidence, resolve a clear or vague brief, and develop the current direction before selecting a style or template. Retain compact notes on facts and their sources, unknowns, creative choices, audience, use, style, and the current edit. Preserve valid earlier decisions without treating a rejected direction as fixed. Creative freedom does not establish unknown product facts. Treat a named template as a visual intention to adapt to the inspected item. For non-graphic prompts, lead with 3–5 checkable anchors, while retaining all required reference relations. For graphics, carry the defining relations without a prescribed count. The owning method skill selects a matching template through its local index; no match means composing from the method. User choices and confirmed reference relations override template defaults. A required graphic mechanism or crop overrides sample defaults such as full visibility, while explicit user choices remain fixed. Example-image subjects and props are not implicit requirements.
4. When production uses image prompting or generation, apply the requested model adapter after the visual specification. Read the adapter's task-specific writing guidance and relevant local official sources. Native vector or document work does not require a model adapter. When a requested version or task is undocumented, check primary official documentation and save the relevant text with its source, retrieval date, revision when available, and hash under that adapter's references. Keep source snapshots separate from local interpretation. An unavailable source blocks only the unsupported model claim. Keep model controls and reference-image inputs outside the prompt. For diagnosis, distinguish the model/entry that produced the sample from the desired target model. Unknown facts stay unknown; one result does not establish a model rule. Multiple requested models share the same visual intent.
5. For graphics, choose production only after the design is resolved. Direct generation, native design, and compositing are conditional options under the SOP. Honor explicit code, vector, model, and single-model requests. Use a sketch when it helps resolve a real uncertainty, and revise it when actual anatomy changes the composition. Deliver complete usable prompts for prompt-only work, or produce and inspect the requested graphics, asset files, or identity system. An explicit SVG or code request requires actual source and a preview, not image-generation prompts. Other image-prompt tasks retain the complete-prompt path. When prompts are required, integrate one complete prompt per image or asset, language, and model. State decisive spatial, scale, and occlusion relations first; mention supporting details once. Audit both directions: all required relations survive, and every visual claim comes from visible evidence, user intent, or an applicable default. For reconstructions, carry mandatory subject anchors into complete prompts and applicable layout relations into the chosen production path. Run the analysis workflow's counterexample check before delivery. For person prompts, including new images and grid panels, read [person defaults and proportions](references/person-prompts.md).

Load only relevant methods, normally one primary deliverable method, its needed medium, and the explicitly requested model adapters. A full VI request remains owned by `oneirloom-brand-identity` even when icons or stickers are included. The shared design SOP governs individual graphic composition; the brand method governs decisions across the asset family. Camera, lighting, and analysis are conditional additions. Tutorials reuse existing evidence for prose-only edits and load visual methods only for examples that need them. Unknown models use portable visual language until their actual capabilities are established.

For a card made from an existing image and prompt, follow `oneirloom-prompt-card` without redrafting the prompt or invoking a generation model. Its 3:4 card canvas is separate from any generation aspect ratio written in the prompt.

For Oneirloom-branded watermarks, default to the woven creature signature with white lettering and black outlines. Do not add a watermark automatically to icon assets. Use the packaged asset and placement guidance in [oneirloom-prompt-card](../oneirloom-prompt-card/SKILL.md). Preserve the creature behind the overlapping lettering and the blue threads woven into its strokes. Prefer white lettering unless the user requests another version or inspection reveals a specific readability problem. Outline all Chinese and English lettering and flourishes in the opposite color: black around white lettering, white around black lettering.

## Output contract

- For requested native SVG, code, asset sets, or VI guidelines, follow the selected method's artifact contract instead of forcing standalone prompts. Deliver actual usable files or source and the relevant previews. A contact sheet does not replace individual assets, and one brand-board image does not establish a complete VI system. A full VI requires the agreed foundations, applications, guideline book, and usable files. State outstanding scope and unverified exports.
- For finished graphic designs, deliver the final preview and actual inspection status. Include editable source and required assets when the chosen path or request warrants them. A written specification is not a finished graphic. Use existing production tools; an unavailable tool blocks only its dependent work.
- For prompt-only graphic requests, deliver complete usable prompts for the selected production path. A direct-generation prompt covers the whole composition; a composite path includes necessary asset prompts and assembly guidance. Do not force asset-only delivery. State which outcomes remain unrendered or uninspected. Complete prompts also remain the default for other image-prompt tasks.
- For each required image or asset prompt and explicitly requested model, or one portable version when unspecified, give a complete Chinese prompt followed by its semantically equivalent English counterpart. Follow an explicit single-language request instead. Preserve all visual details across languages.
- Put each complete prompt in its own copyable block. Keep titles, numbering, language labels, explanations, reference inputs, masks, seeds, and other entry controls outside. Include controls only when confirmed and useful.
- Default generation prose to affirmative, concrete, observable image states: shape, spatial position, direction, visible coverage boundaries, openings, connectors, layer order, and material appearance. Rewrite 'do not get it wrong', 'not ordinary hosiery', 'keep consistent', or 'ensure correct' as the intended visible construction. This is a semantic rewrite, not a ban on individual words; preserve literal in-image text and every required relation.
- Keep counterexamples, error lists, and acceptance commentary internal unless the user requests them; requested analysis stays outside copyable generation prose. Supply a separate negative prompt when explicitly requested or required by a confirmed entry's separate negative field. Keep it separate from affirmative prose; alternatives and other formats remain request-dependent.
- For portable Doubao use, separate instructions to the collaborating assistant from the complete prompts to paste into the image tool. Put ordinary reference-upload instructions outside the prompt blocks. Do not claim Doubao installs or invokes these skills, and do not invent entry controls. The bilingual default still applies unless the user requests Chinese only.
- For edits, describe the target change and the relations that must remain. For prompt corrections, change the requested main dimension where possible and return the complete revised prompt. For graphics, repair understanding, observation, design, or execution as the evidence requires. Use an available editable source for local layout corrections, preserve successful content, and return the requested revision with its actual review status.
- Do not invent original prompts, camera specifications, model capabilities, or success rates. A prompt without an inspected generated result is untested. A stored example demonstrates its recorded prompt and settings, not a subsequently edited template.
