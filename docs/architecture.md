# 主技能与子技能的协作契约

## 一次请求的路径

```text
主技能：继承约束、识别任务
  → 视觉分析（需要参考图或抽象意图时）
  → 镜头与光色（相应维度重要时）
  → 一个表现形式分支
  → 一个或多个明确请求的模型分支
  → 诊断分支（已有结果跑偏时）
  → 主技能整合并交付
```

这是内容路由，不是自动工具调用协议。运行环境需要能按技能 `name` 找到子技能；在仓库内可以读取相邻 `SKILL.md`。若单独安装主技能而未安装子技能，应执行通用流程并说明未加载专用分支，不假装已有模型专门规则。

## 责任边界

| 信息 | 归属 | 其他模块怎样使用 |
| --- | --- | --- |
| 任务类型、会话偏好、输出数量与格式 | 主技能 | 作为所有分支的约束 |
| 可见事实、3–5 个锚点、未知项 | 视觉分析 | 供镜头、光色、风格模块展开 |
| 相机与主体、透视、遮挡、裁切 | 镜头构图 | 形成可检验空间句 |
| 分区颜色、光向、明暗与材质受光 | 光色 | 形成可检验光色句 |
| 媒介细节 | 表现形式（选一个主分支） | 限制镜头和质感词的适用性 |
| 精确模型／版本／入口／任务字段 | 模型分支 | 区分正文与控件，核对官方事实 |
| 本轮偏差、保留项、单变量修正 | 诊断 | 返回完整替换提示词 |

## 冲突解决

1. 用户当前明确要求优先于默认设置；会话内已确认的要求优先于通用模板。
2. 可见参考图事实与用户创作变更发生冲突时，以用户明确变更为准，并保留其他可见关系。
3. 模型官方功能与当前入口不一致时，以当前入口为准；没有入口证据时仅输出可移植文本，不编造字段。
4. 两个风格互相冲突时，确定主风格与局部借用特征。由风格模块提供可见属性，模型模块不得悄悄替换画面审美。
5. 输出负面词须由用户明确请求。任何“禁止某物”的视觉意图先尝试转写成目标状态；画内文本原样保留。

## 新增分支

新模型：增加独立 `skills/vpd-model-<version>/SKILL.md`，写精确版本与入口矩阵、官方 URL、证据等级、任务模式、与正文分离的参数；更新路由和结构检查。新媒介：优先扩展现有风格分支的 `references/styles.md`，只有触发场景与执行步骤确实不同才增加子技能。这样避免每个审美形容词都变成独立技能。

## 验收与评测

结构检查负责文件与路由一致性。行为案例覆盖继承上下文、风格不机械化、参考通道职责、局部编辑和最小修正。实际效果需同入口对照：固定模型、版本、画幅、参考图、种子或采样方案，只改变目标提示词维度；记录输出和判据。至少跨不同主题与风格检查，避免针对一张图过拟合。
