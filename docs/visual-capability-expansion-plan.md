# Oneirloom 视觉能力扩展与旧知识吸纳方案

**状态：已批准的源码实施方案。** 初稿日期为 2026-10-10，方案于 2026-10-11 获准实施。0.3.0-preview 源码现包含本方案中的三个新方法、职责路由、基础 references 和拼豆迁移。发布包、安装状态和图像验证未随本次源码实施改变；实施证据见 [0.3.0-preview 源码记录](../work/visual-families-20261010/implementation-0.3.0-preview.md)。

本方案保留十类视觉分类作为找方向的目录，调整方法职责，新增工艺构造、数字造型、空间构想三个 Skill，并按用途迁移旧知识。外部风格按可见机制吸纳。十个分类不对应十个新 Skill，也不意味着当前源码已完整覆盖十类能力。

本方案的近期目标是把正确的职责与阅读关系搭起来，使每个新增方法具备最低限度的判断、输出和纠错方法。源码已按此目标实施；后续按真实需求补内容，不把预设风格条目数量或一次性导入全部外部风格和旧模板设成完成门槛。

## 1. 把分类、方法和配方分清

用户说“想找一种视觉方向”时，分类目录帮助发现选择；用户说“就用水彩”时，直接使用插画方法。Skill 决定怎么做，reference 展开某个问题的知识，template 保存一种具体做法，例图与记录说明这份做法实际得到过什么结果。

| 文件类型 | 放什么 | 不承担什么 |
| --- | --- | --- |
| 分类目录 | 十类名称、检索词、边界、方法与条目链接 | 完整技法、所有模板内容、自动调度 |
| 方法 Skill | 适用任务、关键判断、组合规则、输出与纠错 | 按每个风格名称重复建立入口 |
| 方法下的 references | 单一负责人维护的材质、叙事、造型等知识；可有跨分类标签 | 第二套复制的分类库 |
| 方法下的 templates | 具体构造、不可丢的关系、可调变量、完整配方 | 替所有任务决定主题、构图和内容 |
| 例图与证据 | 原始提示词、图像、已知入口与参数、观察和偏差 | 为后来改写的配方背书 |

目标文件关系如下。图中的三个新方法现已存在于 0.3.0-preview 源码中。

```text
skills/oneirloom/SKILL.md                    按当前任务选择必要方法
  references/interaction-contract.md       共享交付与连续对话规则
  references/visual-families/               可选的十类检索目录
      index.md + 十个分类说明               只链接知识和方法

skills/现有方法/SKILL.md                    保留或调整职责
  references/                              该方法负责的知识正文
  templates/<recipe>/                      具体配方及原始例图、记录

skills/oneirloom-craft-construction/        新增，工艺构造
skills/oneirloom-digital-form/              新增，数字造型与视觉变换
skills/oneirloom-space-conception/          新增，空间构想
```

这是文档组织与按需阅读关系，不增加运行引擎、固定层数或必经流程。保留[现行架构](architecture.md)和[已接受迁移的原因与约束](architecture-progressive-disclosure-proposal.md)中的渐进披露、直接调用、单一知识归属、模板可选原则。一个任务由当前负责交付的方法整合相关知识，读取另一个方法不等于转交聊天或启动另一个代理。

## 2. 先承认现有覆盖的深浅

本方案实施前，源码有十九个 Skill，公开冻结预览版有十八个，织梦为第十九个本地试用入口。0.3.0-preview 源码现有二十二个 Skill，保留原十九个并新增三个方法。十类目录及说明仍是覆盖不完整的基础内容；[既有检查](../work/visual-families-20261010/checks.md)只证明实施前的文件、链接和标签结构，不证明方法覆盖或图像效果。

以下列出本方案实施前基线发现及其依据；对应源码缺口已按上文方案纳入 0.3.0-preview 源码。该处理不表示十类条目或关联方法已达到完整覆盖。[设计入口](../skills/oneirloom-style-design/SKILL.md)宣称支持工艺，其[领域表](../skills/oneirloom-style-design/references/styles.md)却没有工艺行，3D 只有一行。摄影的[建筑摄影行](../skills/oneirloom-style-photography/references/styles.md)检查透视与立面，不解决空间方案。时装目录遗漏角色衣橱方法，材质目录遗漏已负责材质受光的色光方法。主入口 metadata 没有明确宣传跨媒介探索，分类 index 又要求先选已有媒介，削弱了发现新方向的用途。

| 分类 | 方案实施前的挂靠与覆盖 | 本方案确定的负责人和处理（已用于当前源码） |
| --- | --- | --- |
| M Materials 材质 | 摄影、插画、设计；色光已有基色、透明度和反光判断，目录漏挂 | 色光负责表面响应；工艺负责构造；绘画痕迹归插画。补材质知识和正确链接 |
| P Photography 摄影 | 摄影已有构图、动作、成像与具体场景配方 | 保留摄影；按需要增加具体成像技法，不重建入口 |
| C Cinema 影视 | 摄影已有电影剧照一行与叙事情境提示，尚无完整静帧组织方法 | 在摄影下补静帧叙事与场面调度 reference；限静态画面，插画电影感也可直接引用 |
| A Illustration 插画 | 插画已有媒介、线条、色层、版画等检查和配方 | 保留插画；扩充缺失技法，不把实体纸构造都塞入插画 |
| G Graphic 平面 | 设计已有完整图文理解、观察、设计、生产与复核流程 | 保留设计，解除孤立工艺和数字造型的兜底职责；专题图文模板仍在这里 |
| R Craft 工艺 | 设计笼统挂靠；拼豆模板已有扎实具体知识 | 新增工艺构造；吸收单元、连接、层次、边缘与支撑判断 |
| D Digital 数字 | 设计一行 3D，插画能处理部分合成外观 | 新增数字造型；处理体积、数字变换、合成关系，按输出区分渲染图和原生资产 |
| S Space 空间 | 设计、摄影、镜头能呈现与取景，缺空间构想 | 新增空间构想；建立体块、围合、开口、邻接和尺度方法，摄影继续负责如何拍 |
| F Fashion 时装 | 摄影有时尚抓拍；角色衣橱有造型对应；分析有服装结构证据 | 补角色设定的造型搭配 reference 并映射现有方法。原创服装设计、制版和工艺仍标待扩展 |
| T Product 产品 | 产品美术指导成熟部分集中在已有真实产品及其广告 | 真实产品仍归产品；虚构外形概念可用数字造型，包装图文归设计。工业设计与可制造性不在本轮承诺内 |

“材质”“时装”“产品”是横跨媒介的检索维度。同一条知识可以被多类链接，但正文只有一处。类别完整与方法可用分别记录，不能用十个文件代替能力建设。

## 4. 新增三个有判断内容的方法

以下三个路径已加入 0.3.0-preview 源码。三者读取既有[共享交互契约](../skills/oneirloom/references/interaction-contract.md)，保持直接调用。它们先解决视觉构想与表达，不承诺尚无工具和证据支撑的制造、建模或施工成果。

| 新方法与文件 | 输入、核心判断和输出 | 边界、合作及首个文本例题 |
| --- | --- | --- |
| `skills/oneirloom-craft-construction/SKILL.md`；`references/construction.md` | 输入主体、媒介或构造意图、可保留与可变关系。判断基本单元、排列、连接、层厚、边缘、支撑、手工不规则与尺度。输出明确构造的完整提示词，或供当前交付整合的构造说明；用单元融合、层次消失、悬空连接等失误指导修正 | 材质受光引用色光，画面层级归设计。视觉样机不等于可制作图纸。例题为把用户头像转成拼豆，保留识别结构并区分平面图案角度与实体俯拍角度 |
| `skills/oneirloom-digital-form/SKILL.md`；`references/form-and-transformation.md` | 输入主体、数字变换目标、期望资产类型。判断轮廓与体积、离散或连续单元、重复与变形规则、空间连接、材质与反射、合成层次。输出完整画面描述或数字造型说明；针对体积扁平、变形破坏身份、反射不连续修正 | 色光拥有材质响应，图文构图归设计。已有包装事实仍归产品。渲染图不称可编辑模型；原生模型请求另核可用工具及真实文件。例题为透明分层的虚构香水瓶外形概念，明确仅视觉概念 |
| `skills/oneirloom-space-conception/SKILL.md`；`references/spatial-relations.md` | 输入用途或场景意图、已知尺度、固定物件、真实或虚构条件。判断主要体块、围合与开口、邻接、可见通行、焦点、尺度参照、前中后层。先构成空间，再选择观察位置；输出空间说明与完整提示词，纠正无通路、尺度冲突、开口无因等问题 | 相机方法拥有投影，摄影拥有拍摄表现，色光拥有光照。平面关系草案不称施工图，视觉连贯不证明工程安全。例题为可看见入口、展示岛和后墙的纸艺展厅概念 |

共同的最低完成条件是入口能判断何时使用、能完成上述例题的文字方案、能指出一次典型失误该改哪里，并能说清输出尚未验证的部分。只有名称、简介和空 references 的目录只能叫占位骨架。即使达到这套文字条件，生成质量仍为待验证。

三项新增各有独立判断对象。工艺解决“怎样组成”，数字解决“怎样塑形或变换”，空间解决“怎样组织场所”。将它们继续塞进平面设计会保留现有职责混乱；按十个分类各建 Skill 又会重复材质、主体和媒介知识。采用三个新方法的成本是维护更多入口，收益是分类能指向真正负责该问题的方法。

## 5. 整改阅读顺序与知识归属

先修改[主入口](../skills/oneirloom/SKILL.md)的 description 和任务表，明确支持跨媒介探索。再修改[分类 index](../skills/oneirloom/references/visual-families/index.md)首段，取消“先选择已有媒介再读分类”的要求。保留已确定风格直接进入方法的路径。

新的顺序由当前缺口决定。

1. 判断交付类型，保留已确认的事实与选择。真实产品在提出创意改造前读取产品规则。
2. 情绪或片段还没有可画场景时，用织梦；场景已经清楚、只是想换视觉方向时，用分类 index。
3. 从用户意图挑相关分类，再读少量能比较的机制与适用范围。不用加载全部十类和全部方法，也不设固定候选数量。
4. 方向确定后读取负责方法和必要支援；找到相符的配方才使用模板。最后按实际请求适配模型或交付原生文件。

知识正文归属和新增文件如下。原有专项检查继续保留，只有明确抽出的通用部分改成链接。

| 唯一正文位置 | 应纳入的内容与调用方 |
| --- | --- |
| 已新增 `oneirloom-color-light/references/material-response.md` | 表面基色、反射、粗糙度、透光与尺度线索；M 分类和所有相关方法链接。既有透明面料证据细则留在原 reference，不重复抄写 |
| 已新增 `oneirloom-style-photography/references/still-frame-staging.md` | 画面内事件、人物关系、视线、动作瞬间、调度、景深与明暗叙事；C 分类、摄影及需要该叙事的插画读取 |
| 已新增 `oneirloom-character-sheet/references/fashion-styling.md` | 造型轮廓、服装搭配、层次与配饰关系、系列差异和身份连续；F 分类、衣橱页和单张时尚图读取。服装证据检查仍引用 visual-analysis |
| 三个新方法的 references | 各自完整的构造、造型、空间知识；R、D、S 分类链接。分类说明只写选择信号和范围 |
| 现有方法的 styles、templates/index | 继续承担本方法内的精确选择；删除已经迁出的正文，改为明确链接，不另设全局模板总表 |

分类说明与 index 必须一起改。M 补色光，F 补角色设定，R/D/S 指向新方法并写明已覆盖与待扩展部分。P/A/G 保持原归属，C 指向静帧知识，T 分开真实产品展示和虚构外形概念。更新设计 SKILL 的标题、metadata、“Other design tasks”及领域表，避免正文仍自称全能兜底。旧三份 styles 表的分类链接可保留。

有重叠时按所做的决定区分。“纸质感”可能是纸面反光，归色光；纸上颜料与留白归插画；纸层折叠与连接归工艺；纸片和文字的阅读顺序归设计。“透明树脂瓶”若描述在售瓶身，事实来自产品；若把既有商品变成树脂雕塑，应明确是获准的视觉变体，不能据此改写所售物品材质；若从零构想虚构瓶体，则由数字方法提出外形，不补造工业性能。

同一个任务保持一份当前方案，不让用户在方法之间来回确认。

| 请求 | 预期阅读及整合结果 |
| --- | --- |
| “写一个水彩街景提示词” | 直接插画与共享契约。媒介已明确，不读十类 index；透明色层、纸白和边缘进入完整提示词 |
| “这个街景还能用什么视觉做法” | index 加与意图相关的候选知识，比较可见变化；确定纸层场景才读工艺，确定数字变形才读数字。不能先锁定摄影或插画 |
| “给这款真实饼干做纸构造海报” | 产品锁定包装、数量与已知事实；设计负责海报和文案；工艺描述独立纸层布景与支撑；必要时色光供纸面表现。由当前交付方整成完整提示词，不把饼干改成纸制商品，不增加用户确认回合 |

共享契约继续拥有完整肯定式提示词、所需语言、独立代码块、字面文案、控件外置和事实证据规则。原生 SVG、代码、文件集、手册仍交付其真实文件。模型适配发生在视觉意图之后，未知入口只给可移植文字。不得为此次扩展引入新问卷、固定轮数或审批关卡。

## 6. 吸纳旧知识时保留已经做对的细节

先按知识用途分三类。多个任务都需要的判断进入方法；只在某类任务用到的细节进入该方法的 reference；决定一个具体效果的构造、版式与完整提示词留在 template。模板中的专业知识不能因为“它只是模板”而被丢弃，也不能把具体样例默认值提升成通用规则。

独立分发一个方法时，必须包含其所需共享契约、references 与跨方法资源，或确认安装方式能够解析它们。“模板在自己目录里”只解决例图归属，不等于单独复制该文件夹就能运行。实际分发检查属于后续获准安装或打包的范围。

## 7. 吸纳外部分类和未来风格

十类视觉分类用于本地检索和组织，不代表已经导入外部风格库。当前方法正文由我们独立编写，或从已审阅的本地模板提炼；具体风格内容按实际需求逐条扩充。

分类借鉴与内容导入分开。分类名称用于本地组织；方法解释由我们根据公开可见机制独立撰写并记录来源。若要复制某个开源条目或代码，先核对该文件适用的许可证、范围和署名要求。权限不明时只保留链接与来源线索，不导入原 JSON、原段落或图片；不访问付费内容或绕过登录。出现访问限制只停止受影响来源，独立编写仍可继续。

每次吸纳从一个有实际用途的风格开始。

1. 判断它属于现有知识、一个同义词、一个新机制，还是具体配方。优先合并同义词和已有正文链接。
2. 选择负责方法，在其 `references/` 写知识条目；条目少时用现有相关文件的章节。只在形成可复用具体构造时建立 template。
3. 用可观察的关系说明效果，写出适用条件、可改变量、常见失误和修正；有来源图时区分观察与推断。
4. 在相关分类说明增加简短检索项，链接唯一正文。保留来源与证据状态，后续实际生成只给本次版本增加证据。

条目使用普通 Markdown，正文中保留必要字段即可。无需数据库、全局注册服务或另一份完整目录。

| 字段 | 用途 |
| --- | --- |
| 稳定 ID、名称、搜索同义词 | ID 不随中文标题调整而变化；多个叫法检索同一条正文 |
| 分类标签、唯一方法负责人 | 可同时属于 M/R/G；唯一正文路径避免重复维护 |
| 可见机制、适用范围 | 描述实际边缘、层次、形变、光色与构图效果；指出哪些任务不适合 |
| 可改变量、易失败处、修正办法 | 说明改什么会改变结果，哪些关系必须保留 |
| 来源、复用依据、证据状态 | 链接、读取日期、作者信息在已知时记录；区分独立编写和获许可导入，未知保留未知 |

例如已写入[构造 reference](../skills/oneirloom-craft-construction/references/construction.md)的 `craft.layered-paper-relief` 带 M/R 标签，归工艺方法。可见机制是有厚度的纸层、层间遮挡、切边和接触阴影；变量是层数、间隔、配色和观察角度；失误是整张变成平面印刷；修正应增加构造与光影关系。该指导尚无生成结果。具体海报应用仍可成为设计模板，引用这条知识。

知道某个风格名称、写出合理机制、形成可用配方、得到并检查结果、证明可重复，分别是不同事实。目录无需隐藏未实测知识，但必须让读者知道它能支持哪一种判断。外部介绍中的条目数量，不能变成本地能力数量或导入配额。

## 8. 按最小完整单元实施和验收

以下是方案的实施和验收顺序。第 1、2 步已在本地 0.3.0-preview 源码中完成；源码与迁移保全证据见 [实施记录](../work/visual-families-20261010/implementation-0.3.0-preview.md) 和 [迁移记录](../work/visual-families-20261010/migration-preservation-0.3.0-preview.json)，十条实际 source-guided text cases 见[视觉路线报告](../work/visual-families-20261010/text-exercises-visual-0.3.0-preview.md)及[连续交付报告](../work/visual-families-20261010/text-exercises-continuity-0.3.0-preview.md)。第 3、4 步仍按实际需求执行，不阻塞已完成的源码骨架。

| 顺序与负责写入范围 | 具体改动 | 对应完成证据 |
| --- | --- | --- |
| 1. 当前源码职责和阅读骨架 | 更新 `docs/architecture.md`、主入口、十类目录和设计边界；创建三个新方法及其基础 references；补材质、静帧、造型搭配 references 和条件链接；更新 `PROJECT-FILES.md`。先使新入口可读，再切换旧路由，整组验收 | 相关本地链接闭合；修改及新增 SKILL 通过现有针对性 validator；十九个旧入口仍存在。文本走查证明明确水彩直达、未定媒介先探索、新方法各有判断和输出。只标“源码基础内容与方法”，不标十类已完成 |
| 2. 已审阅旧知识的迁移 | 第 1 步之后，迁移拼豆及调用方，提炼 3D、盲盒、衣橱、静帧中已确认的通用知识。一个写入者处理耦合路径 | 迁移前后图片和归档提示词哈希相同，历史记录保留；活动链接和实际读取路径有效；核对拼豆单元、盲盒上下关系、衣橱对应等语义未丢 |
| 3. 按实际需求扩充风格 | 使用第 7 节接收选定条目，只更新其负责人正文与相关分类链接。未审阅旧模板保持不动 | 每个条目能说明来源、归属、机制、失误和证据状态；没有第二份正文或虚构案例。完成约定条目即结束这一批 |
| 4. 需要图像能力证明时再做实际验证 | 仅在另获生成授权且有明确目标时，用实际入口生成、检查并修正选定案例；沿用现有例图记录格式 | 保存实际提交提示词、入口、输出及观察。只对观察到的范围下结论；未运行、未检查和重复性未知分别标明 |

第 1、2 步已完成方案要求的源码职责调整、已审阅拼豆知识迁移和针对性文本走查。视觉路线五案初次运行有 4/5 案符合标准，唯一初始失败是 case 1 英文提示词漏掉“街道无人”；手动、非盲修正了 case 1，并去掉 case 2 未被要求的英文译文（case 2 原标准已通过），case 3–5 保持不变，修正后的视觉五案均通过。连续交付 case 6–10 五案均通过。原始回复及 case 1 初始失败保留在报告中，回复修正没有修改源指导。该证据是按已读本地源码生成的非盲文字响应，不代表新安装会话、自动路由或图像质量。对应报告保留标准、实际输出和来源哈希。第 3 步才逐步扩库；已完成源码范围之外的条目仍按真实需求扩充。前三步的文件工作不需要强行打包、发布或运行全套测试；这些操作仍需各自明确授权。

职责分工沿用既有规则。架构负责人确认本文和关键边界；执行者按已接受设计实施；Primary 审查实际 diff 与关键证据。每个文件只有一个写入者，主入口与十类 index 的切换由同一整合者处理。三个新方法的正文可在职责已明确后独立准备，整合前不得把未存在的路径写成已可用入口。

验收使用实际文本输入与输出，而不只搜索关键词。至少覆盖本方案第 5 节三条阅读路径，以及新方法的三个例题；真实产品纸构造例必须保留事实与布景的区分。还要走查“只改背景”“给 SVG 文件”“未成形记忆”“未知模型入口”这些受现有契约约束的分支，确认没有被新分类强制重走探索或变成图片生成。保存实际读取文件与响应；设计者写的理想答案只能作预期，不能冒充运行证据。只复用相关既有检查，不建新评测框架。

开始每个迁移单元前保存该单元文件的当前字节和哈希，区分原有脏改动与本轮修改。已有分类骨架的临时备份只能帮助定位此前变化，不能作为全仓恢复点。遇到后续用户改动时停下受影响的覆盖，按当前内容重新合并。撤销只恢复本单元拥有且未被后续修改的内容；迁移失败先从自己的备份恢复文件及调用方，不使用 stash、reset 或 clean。

0.3.0-preview 源码实施了本方案的第 1、2 步，并完成了上述十个本地 source-guided text cases。冻结的十八项 v0.2.0-preview.1 包、安装缓存和发布状态未随源码更改。源结构检查及所记录的文字响应不证明新安装会话中的自动路由、图像生成与质量、原生模型文件、工程可行性或重新分发；需要图像能力证明时仍按第 4 步另行授权和验收。
